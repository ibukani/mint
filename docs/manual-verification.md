# 手動検証手順 (Manual Verification)

Mint アプリケーションの E2E テスト（`npm run test:e2e`、Windows 実バイナリ）が自動検証する項目は、リリース前や大幅な機能改修後にも自動で確認されます。この手動検証は、E2E でカバーされない項目を中心に実施してください。

## UI変更時の必須確認

UIまたはdesktop挙動を変更した場合、`npm run tauri -- dev` で実際のTauriデスクトップアプリを起動し、影響する画面・操作を確認します。以下の共通確認と、変更に関係する機能別の項目を実施してください。変更のない機能全体を毎回再確認する必要はありません。

1. 設定画面の変更は900×650・680×520、overlayの変更は実寸で確認し、ライト/ダークテーマを確認する。共有layoutの変更では関連画面も確認する。
2. 実機スクリーンショットを取得し、欠け・横溢れ・余白・整列・文字折り返し・コントラスト・テーマ・スクロール・overlayの重なりを目視確認する。キーボードfocusと操作はlive windowでも確認する。
3. 不自然な点があれば修正し、実機で再確認・再撮影する。変更した操作・表示の不具合が解消したことを確認する。
4. 引き渡しにはOS・サイズ・テーマ・画像の保存先・目視確認結果・未確認項目と理由を記載する。実機未確認の動作を確認済みとして完了扱いにしない。

ブラウザ画面やモック画面だけのスクリーンショットは証跡として扱わない。ブラウザmockは補助確認に使い、現在のE2Eで確認した同じ動作を手動で重複確認する必要はありません。ただしE2Eの成功だけで上記の画像・focus・表示品質の確認を省略しません。

### リサイズ不可windowのサイズ別確認

mainは現在 `resizable: false` です。680×520や大きいサイズの確認では、現行 `src-tauri/tauri.conf.json` を `tmp/ui-verification.json` に複製し、mainのwidth/heightだけを検証サイズへ変更します。`npm run tauri -- dev --config <検証用設定の絶対パス>` で起動してください。windows配列を含む全window定義を保持し、配布設定のresizableやcapabilityは変更しません。

保存済みの位置・サイズが検証サイズを上書きする場合は、debug専用の `MINT_E2E_DATA_DIR` に `tmp/` 配下の使い捨てディレクトリを絶対パスで指定して検証します。元の環境変数値を退避し、検証後に戻してください。実際に表示されたサイズを確認・記録します。

## 自動検証（E2E）の範囲

`npm run test:e2e` で自動検証される項目（詳細は `e2e/README.md` 参照）:

- アプリ起動とメインウィンドウ表示（タイトル、ルート要素、テーマ適用）
- 設定の保存と再起動後の復元（テーマ変更 → 再起動 → 反映）
- 時計オーバーレイの開閉
- 廃止機能の設定移行・バックアップ・保存データ保持・呼び出し拒否
- 正常終了とプロセス残存なし

## 対象プラットフォームと画面サイズ

Mint は Tauri のデスクトップ専用アプリです。スマートフォン向けのレイアウトやタッチ操作は手動検証の対象外とし、次のデスクトップ条件を確認します。

- メイン設定画面: 通常サイズ（1280×900前後）、既定サイズ（900×650）、最小サイズ（680×520）
- オーバーレイ: 時計（420×168）、カレンダー（420×384）、ゲームランチャー（760×520）、予定編集（420×640）、Mint Palette（640×420）
- ダーク/ライトテーマ、キーボード操作、ウィンドウのドラッグ・最小化・クローズ

## UI変更時の必須確認

UIを変更した場合は、ブラウザの補助確認に加えて `npm run tauri -- dev` で実際のTauriデスクトップアプリを起動し、影響するウィンドウを対象サイズとダーク/ライトテーマで確認します。ブラウザ画面やモック画面だけのスクリーンショットは証跡として扱わないため、実際のアプリ画面を撮影してください。

スクリーンショットとライブ画面で、欠け、横溢れ、余白、整列、文字の折り返し、フォーカス、コントラスト、スクロール、オーバーレイの重なりを目視します。不自然な点があれば修正し、再撮影して問題が解消したことを確認します。完了報告には確認したサイズ、テーマ、実機スクリーンショット、未確認項目、残存リスクを記載してください。

## 1. アプリケーション起動
1. `npm run tauri -- dev` を実行。
2. アプリケーションのウィンドウが正常に表示されることを確認。
3. デベロッパーツールを開き、コンソールにエラーが出ていないことを確認。
4. インストール済みリリース版で設定を変更して完全終了した後に開発版を起動・終了し、リリース版を再起動しても設定、保存データ、API キー、Google Calendar 接続、自動起動設定が変化していないことを確認する。

## 2. 機能管理ダッシュボードの設定保存と永続化
1. 機能管理ダッシュボード（設定画面）で「テーマ」を切り替える（ダーク / ライト / システム）。システムを選んだ場合はOSの外観設定変更に追従することを確認する。
2. アプリを完全に終了し、再起動。
3. 変更したテーマが維持されていることを確認（`settings.json` への永続化テスト）。
4. `Ctrl+K`（macOSは `Command+K`）でクイックランチャーを開き、「時計サイズ」「テーマ設定」などの設定項目を検索して選択すると、該当する入力欄へフォーカスとスクロールが移ることを確認する。「時計を開く」「カレンダーを開く」などの操作を検索して選択した場合は、対応するオーバーレイが表示され、「今日の予定を追加」では予定入力画面が今日の日付で開くことも確認する。無効化中の操作には実行前に「無効」と理由が表示され、選択してもランチャーが閉じず、「詳細設定を開く」で対応する有効化スイッチへ移動でき、設定変更後に再試行できることを確認する。成功した設定・操作は次回ランチャーを開いたとき「最近使った項目」として候補の先頭に表示され、アプリを再起動しても維持されることを確認する。「ライトテーマにする」「ダークテーマにする」「システムテーマにする」を選ぶと、設定画面を移動せずテーマが切り替わることも確認する。実行中の予期しないエラーではランチャー内にエラーが残り、再試行できること、「クイックランチャーの検索をクリア」で一覧へ戻れること、設定値の入力欄にフォーカス中は同ショートカットが入力操作を奪わないことも確認する。

## 3. ショートカットとトレイメニュー
1. 時計機能のショートカットキー（デフォルト等）を変更し保存。
2. 変更したショートカットキーを入力し、時計オーバーレイが表示・非表示されることを確認。
3. トレイアイコンを右クリックし、メニューから「ダッシュボードを開く」「終了」などの操作が動作することを確認。

## 4. ウィンドウとオーバーレイ
1. 時計オーバーレイが指定秒数後に自動非表示になるか確認。
2. Discord風の「×ボタンで最小化（トレイへ）」が機能し、プロセスがキルされないことを確認。
3. メイン設定画面と時計・カレンダー・ゲームランチャー・予定編集を一度開いて閉じ、2分以上操作しない。各WebViewが破棄された後も、トレイ/設定ショートカットまたは各ショートカットで再生成されて正常に表示されることを確認する。CPU/RSSの値はOS、WebView、GPU、表示倍率、開発/リリースモードで変わるため、同一PC・同一モードでの前後比較として記録する。
4. メイン設定画面とゲームランチャー・カレンダー・予定編集を別の位置へ移動して閉じ、再表示時に位置が復元されることを確認する。固定windowのサイズ別確認は上記の検証設定を使う。カレンダーは位置だけを永続化する。復元できない場合は既定位置に表示されることを確認する。
5. マルチモニター環境で、保存した状態のウィンドウを別モニターに移動して閉じた後、そのモニターが外れた状態で再起動して開くと、ウィンドウが画面外に出ず操作可能な位置に表示されることを確認する。
6. 設定画面の一般設定「位置・サイズ」で各ウィンドウの「リセット」を押すと、位置・サイズの記憶が消え、次回以降は既定位置に表示されることを確認する。

## 5. カレンダーとGoogle Calendar連携
1. カレンダー設定を開いた直後に、接続確認中の表示を経てから未接続または接続済みの状態が表示され、確認中に未接続画面が一瞬表示されないことを確認する。
2. Googleアカウントを接続し、ブラウザ認証の待機中もMintのウィンドウ移動・設定画面のスクロール・別機能への切り替えが固まらないことを確認する。認証のキャンセルと時間切れでは再操作方法を含むエラーが表示されることも確認する。
3. 接続後に予定表ごとの表示切り替えと、編集可能な予定表だけを新規予定の保存先に選べることを確認する。表示できる予定表がない場合は空状態と再確認操作が表示されることを確認する。月表示の前月／次月ボタンで移動した場合も、同じ日付のグリッドへ選択とフォーカスが戻ることを確認する。「次の予定」を選ぶと予定の月へ移動して詳細を開き、戻るとその月の表示へ戻ることも確認する。
4. 「今すぐ同期」の実行中に進捗が明示され、連打できないことを確認する。カレンダーオーバーレイ表示時の自動同期は、同じ予定表を5分以内に同期済みなら再通信せず、予定表の選択変更または鮮度期限後には同期することを確認する。自動同期と手動同期が同時になった場合も、操作が順番に完了して予定の重複や消失がないことを確認する。オーバーレイの同期失敗時は原因と「再同期」が表示され、通信復旧後に再試行できることも確認する。月表示の「日付」から遠い日付を選ぶと、その月へ移動して選択日へフォーカスが移り、`G` でも日付選択へフォーカスできることを確認する。
5. オフライン、認証切れ、APIエラーから復帰後に再同期でき、更新件数または最新状態の完了メッセージと最終同期日時が表示されることを確認する。ローカル予定の読み込み失敗時は、月表示・日表示のどちらにも「再読み込み」が表示され、復帰できることも確認する。
6. 未同期の変更がある場合は件数と必要な操作が表示され、接続解除が無効になることを確認する。同期後は接続解除でき、Google由来の予定と接続状態が消えることを確認する。
7. メイン設定画面の1280×900、900×650、680×520で、ダーク/ライトテーマともにアカウント、予定表一覧、保存先、状態表示、操作ボタンが横にはみ出さないことを確認する。
8. 予定の編集中に閉じる操作またはEscapeを入力すると、未保存の内容を破棄する確認ダイアログが開くことを確認する。初期フォーカスはキャンセル、Tabはダイアログ内を循環し、Escapeまたはキャンセル後は入力内容と元のフォーカスが維持されることを確認する。保存処理中は閉じる操作が無効になることも確認する。カレンダーを表示したまま予定を保存した場合は、月表示・日表示の一覧と開いている予定詳細が保存内容へ自動更新されることを確認する。予定を別の日付・別月へ移動して保存した場合も、詳細の日時と戻り先の日付が保存内容に追従することを確認する。
9. 予定詳細の「詳細をコピー」または `C` で、タイトル・日時・メモが改行区切りでクリップボードへ入り、成功表示が出ることを確認する。クリップボードが利用できない場合は、予定を失わずエラーが表示されることも確認する。
10. 予定詳細の削除では確認前に削除されず、キャンセル後は削除ボタンへフォーカスが戻ることを確認する。削除失敗時はダイアログ内のエラーから再試行でき、Google由来の予定ではGoogle Calendarにも反映される旨が表示されることを確認する。
11. 日表示を開いたとき、予定があれば最初の予定、空の日は追加ボタン、読み込み失敗時は再読み込みへフォーカスが移ることを確認する。前の日/次の日ボタンまたは←→で日付を連続移動でき、月をまたぐ場合も予定が再読み込みされることを確認する。予定にフォーカスした状態で上下キー・Home・Endで一覧内を移動し、Enterで詳細を開けることを確認する。
12. カレンダーを420×384、予定編集を420×640で開き、ダーク/ライトテーマともに月表示の6週・予定マーカー・フッターが欠けないことを確認する。同じ日に4件以上の予定がある場合も月表示の高さが変化せず、日表示では時刻・タイトル・保存元・メモが判別できることを確認する。終日予定では開始日と終了日を指定して複数日の予定を作成・編集でき、詳細には両端を含む日付範囲が表示されることも確認する。

## 6. ゲームランチャー
1. `Alt+1` でゲームランチャーを開き、Steam、Epic Games、Riot Gamesで検出したゲームが表示されることを確認する。
2. タイトル、ストア名、タイトルの略称で検索できることに加え、`counter strike` のような記号をまたぐ入力、全角英数字、`ライオット val` のようなストア別名とタイトルの複数語でも絞り込めることを確認する。「検索をクリア」で一覧へ戻れること、IME変換確定中のEnterでは起動せず、変換中でなければ上下キーで1件、PageUp/PageDownで5件、Home/Endで先頭・末尾へ選択を移動し、Enterで起動できることも確認する。アクションへTab移動した後も `Ctrl+F`（macOSは `Command+F`）または `/` で検索へ戻れることを確認する。
3. ゲームをお気に入りへ追加して先頭へ並び替わった後も、一覧の選択と右側プレビューが同じゲームを保持することを確認する。起動履歴による並び替えでも同様に確認する。
4. 検索中のEscapeは検索だけを解除し、もう一度Escapeを押すと閉じることを確認する。ショートカットの `Alt+1` を再入力した場合は検索状態に関係なく閉じることも確認する。
5. ゲーム行の単クリックでは選択だけが変わり、通常幅では右側、狭幅では一覧下部の明示的な「起動」ボタンでゲームが起動することを確認する。起動中または管理画面を開いている間は、別ゲームを含む競合操作が無効になることも確認する。
6. 760×520と620×520のダーク/ライトテーマで横溢れがなく、通常幅のプレビューと狭幅のコンパクトな選択ゲーム操作が欠けずに表示されることを確認する。起動失敗、管理画面を開く失敗、再スキャンおよびストア読み取りの具体的なエラーが省略されず画面内で確認できることも確認する。
7. Steamのローカル画像キャッシュがある場合は画像が表示され、ない場合はプレースホルダーになることを確認する。ゲームランチャー表示中にSteam CDNなど外部の画像ホストへ通信しないことも確認する。

## 7. アップデーター
1. `npm run dev` を実行し、`http://localhost:1420/?mockUpdate=available` を開く。
2. 一般設定の「アップデート」に、現在・更新後のバージョン、公開日、リリースノートが表示されることを確認。
3. 「ダウンロードして再起動」を押し、ダウンロード進捗、インストール中、再起動中の順に表示が変わることを確認。
4. `http://localhost:1420/` では「更新を確認」を押すと「最新バージョンです」と表示されることを確認。
5. 実リリース前にはテスト用の旧バージョンをインストールし、公開済みの署名付き Release へ更新できることを対象OSで確認。

## 8. 診断情報
1. 一般設定の「診断情報」セクションで「診断情報をコピー」を押すと、動作環境、設定状態、ウィンドウ、カウンター、計測イベント、保存データ件数をまとめた Markdown がクリップボードへコピーされ、「診断情報をコピーしました」と件数サマリーが表示されることを確認する。
2. コピーされた内容に API キーやトークン、メモの本文、予定の内容、ファイルの完全なパスが含まれていないことを確認する。
3. 取得に失敗した場合は「診断情報を取得できませんでした: …」とエラーが表示され、アプリが正常に動作を継続することを確認する。

## 9. プラットフォーム固有
- Windows実機にて、アプリの多重起動が防止されているか（Single Instance）。
- トレイアイコンが Windows 11 のタスクバーで正しく表示されるか。
- Windowsの自動起動は `npm run tauri -- build` で作成したリリース版をインストールして確認する。`npm run tauri -- dev` は `localhost:1420` のViteサーバーを使うため、自動起動には登録されない。
